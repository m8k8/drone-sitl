# 第１弾 B〜D のSITLモデル

実験003用の、購入前の部品表に基づく暫定モデル。第１弾の範囲は飛行・FPV・下向き測距・プログラム制御で、タンク・水・散布装置・RTKは非搭載。質量の基準は[部品表の固定版](https://github.com/m8k8/drone-docs/blob/83dfb0be7130008cc49d900d6633d6adef8740dd/hardware/prototype-01/README.md)の **12.3387kg** とする。重量は公表値・材料計算・仮割当を含み、実測値や上限ではない。

## ファイルと再生成

| ファイル | 内容 |
| --- | --- |
| `components.json` | 部品・数量・質量根拠・仮定した配置。重量の二重計上を避けた機上BOM |
| `mass-properties.json` | 計算に使った各質点・箱の分布、重心、慣性テンソルとSITLに渡す対角成分 |
| `models/nominal.json` | 第１弾の12.3387kgモデル |
| `models/mass-low.json` / `mass-high.json` | 11.8387kg / 12.8387kgの感度確認用モデル。重量公差の下限・上限ではない |
| `defaults.parm` | 全ケース共通の飛行制御・電池・下向き測距設定 |
| `manifest.json` | 固定ArduPilot版、モデル一覧、起動引数、機能の再現範囲、元モデルのハッシュ |

プロジェクトのルートで実行する。

```bash
.venv/bin/python config/prototype-01/generate.py
.venv/bin/python config/prototype-01/generate.py --check
./scripts/prepare-prototype.sh
```

生成器はBOM合計12,338.7g、感度ケースの質量、全ケースの推進・抗力校正値の一致を検証する。準備スクリプトは既存G06モデルの`referenceMass`パッチをハッシュ検査して適用する。実験003のための追加のArduPilotソース変更は行わない。`run.sh`は引き続き標準quad用であり、この設定へ自動で切り替わらない。

## 質量・配置の反映

座標は機首向きがx正、右がy正、下がz正。部品配置の原点をモーター面の幾何中心とする。G06は実物の矩形座標が未確定のため、実験002と同じ対角1.172mの正方形Xを使用する。

- 4基のX6 Plus G2は各モーター中心へ748gずつ配置する。プロペラ・標準配線はその重量の内数。
- フレーム5.4kgは中央3.0kgの箱と、各アーム途中の0.6kg×4へ仮に分配する。タンク非搭載を理由に750gを差し引かない。
- 電池は1.29kg×2。各170×61×58mmの箱を、中心y=±35.5mm、z=180mmへ配置する。電池間のすき間を10mmとした配置案であり、実機での取付確認はまだない。
- トレー、カメラ、GPS、電子機器、配線、取付材もBOMの全質量を配分する。カメラは機首側、GPSはモーター面より上とするなど、取付座標はすべて仮定。

名目ケースで計算される重心は、モーター面の中心から **前方1.48mm・下方55.44mm**。慣性対角成分は約 **[0.72593, 0.75059, 1.31983] kg·m²**。この重心を基準に各モーターの位置を移し、ネイティブSITLのモーメント計算へ渡す。

`SIM_Frame`は慣性の対角成分のみを使う。積慣性と一般剛体の角速度結合項は再現されず、脚・トレー・ケーブルの変形や液体挙動もない。慣性計算用の部品座標は、レンダリング用CADや実物の組立寸法ではない。

±0.5kgケースは、仮定した中央フレーム質量のみを2.5kg／3.5kgへ変える。追加荷物や水を載せる設定ではなく、重量が想定と異なった場合の制御の感度を見る条件である。

## 推進・電池は実験002の校正を維持

`referenceMass=13.4946`と推力・電力・抗力の校正値は[実験002の設定](../g06/README.md)からそのまま引き継ぐ。実質量を12.3387kgへ下げたことを理由に、モーター能力まで変化させない。

12S 10Ah、初期50.4V、内部抵抗0.06Ωという電池条件も継続する。内部抵抗は仮定。電流はネイティブモデルのモーター電流合計であり、カメラ・無線・FC・センサー・DC-DCの消費電力は加算していない。これによる電流・飛行時間は実機の電源容量・端子定格・航続時間の検証値ではない。推力／電力モデルの校正誤差は[既存の校正記録](../g06/calibration.json)を参照する。

## TF02-Proに相当する下向き測距

起動引数`--serial5=sim:benewake_tf03`を使い、UART経由で`RNGFND1_TYPE=27`のBenewakeドライバーへ入力する。ネイティブのTF03シリアルエミュレーターはTF02-Proと共通するパケット形式を使うが、実物TF02-Proを完全に再現するものではない。

- `RNGFND1_MIN=0.1`m、`MAX=13.5`m、下向き`ORIENT=25`。
- エミュレーターの更新は5Hz。実物の標準100Hzとは異なる。
- `SIM_SONAR_RND=0.02`mは試験用の仮定したネイティブ一様乱数雑音。実測したTF02-Proの誤差モデルではない。
- センサーの仮想位置はモデル原点（重心）と同じ。BOMの実取付候補位置は重量・慣性にだけ使う。
- `RNGFND1_GNDCLR=0.1`mは制御器へ与える仮の地上クリアランス。ネイティブの平坦地面の測距値は初期高度を基準とするため、地上ではおおむね0mとなる。これらを実脚の高さや実取付位置と同一視しない。
- `SURFTRAK_MODE=1`で地表追従を有効にする。EKFの主高度源は気圧計のままとし、`EK3_RNG_USE_HGT=-1`でレンジファインダーへの主高度源の切替は行わない。

測距の光学特性、反射率、草・水面、実UART配線、プロペラによる遮蔽は再現しない。ネイティブ機体の地上接触高さは0.1m固定で、実機の脚や下吊り電池の衝突形状はない。

## 機能の再現範囲

| 計画の機器・機能 | このモデルでの扱い |
| --- | --- |
| ArduCopterの姿勢・位置制御、ミッション | 実際の制御コードをホストで実行。Pixhawk基板・CPUの時間特性は再現しない |
| M10 GPS・コンパス | 通常のSITL仮想センサー。M10固有誤差やRTKは再現しない |
| TF02-Pro | 互換UARTパケットと測距入力・制御経路。5Hzの簡易モデル |
| G12 | RC・MAVLink入力。電波伝搬・遅延・映像伝送は再現しない |
| FPVカメラ、Remote ID | 重量と仮配置のみ。画像生成・RF送信は行わない |
| 電源分配、端子、ヒューズ | 重量と仮配置のみ。発熱・短絡・突入・遮断は再現しない |
| microSD | 重量を計上。ログはホストファイルシステムへ保存 |

モデルに部品重量が入っていることと、その部品の全機能が模擬されていることは分けて評価する。
